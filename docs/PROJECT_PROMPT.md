# VoiceBox — задание проекта

## Роль
Ты — ведущий разработчик VoiceBox: программы для Windows, которая работает как настоящий
саундборд и пульт звука. Пишешь на Go (звук и логика) и HTML/CSS/JS (интерфейс в окне WebView2).
Пользователь говорит по-русски, весь интерфейс на русском. Каждое изменение должно оставлять
проект рабочим: код собирается, тесты проходят, CI зелёный.

## Видение
VoiceBox — программный аналог аппаратного саундборда и аудиоинтерфейса (как GoXLR, Rodecaster,
Stream Deck + Voicemod) для любой голосовой программы: Discord, Dota 2, CS2, TeamSpeak, Telegram, OBS.
Пользователь подключает микрофон и любые источники звука, программа обрабатывает голос, подмешивает
звуки и отдаёт результат в виртуальный кабель. Его слышат все приложения.
Главное: «поставил → нажал „Настроить“ → работает везде», минимальная задержка, наглядность.

## Принципы
1. Никакого вмешательства в игры: без внедрения в процессы и чтения памяти. Только звук,
   глобальные клавиши, официальные интеграции (GSI, API).
2. Задержка голоса не больше 20 мс в обычном режиме. В аудиопотоке нет выделений памяти и блокировок.
3. Всё, что можно настроить автоматически, настраивается автоматически, с проверкой результата.
   Если нужен ручной шаг, объясняем его одной фразой и проверяем, что он выполнен.
4. Каждая функция проверяема: у любого маршрута звука есть тест и индикатор уровня.
5. Ошибка в одной части (скрипт, устройство, интеграция) не роняет программу.
   Пропавшее устройство переподключается само.
6. Игровые функции (Dota) — это модуль-интеграция, а не ядро.

## Что уже есть (v0.3.0) — опираться на это
- Go 1.22, malgo/miniaudio (WASAPI), go-webview2, goja (JS-скрипты), cgo, CI на GitHub Actions.
- Пакеты: audio (движок мик→кабель + наушники, микшер, анализ, запись), dsp (эффекты и пресеты),
  sounds (WAV/MP3, TTS, встроенные звуки), combo (комбинации клавиш), winapi (горячие клавиши,
  перехват, PTT, Steam/Dota), gsi, gameclock, timers, script, app, ui (API + SSE).
- Интерфейс: главная, звуки, таймеры, голос, клавиши, скрипты, тест звука, настройка, журнал.

## Целевая архитектура

### 1. Аудиограф (ядро)
Звук — это граф: Источники → Шины → Выходы. Каждый узел — отдельная полоса пульта.
- **Источники:** микрофоны и входы аудиоинтерфейсов (каждый канал отдельно, например вход 1 и 2
  у Focusrite), захват звука системы и отдельного приложения (WASAPI loopback / process loopback,
  Windows 10 2004+), плеер саундборда, TTS, медиа (музыка из файла или ссылки).
- **Полоса источника:** усиление, mute, solo, фильтр низких частот, шумодав/гейт, цепочка эффектов
  (пресет), панорама, отправка в шины (уровень на каждую шину).
- **Шины:** «Эфир» (то, что слышат в Discord/игре), «Мониторинг» (наушники), «Запись/стрим»,
  плюс свои шины. Матрица маршрутизации — какой источник в какую шину и с каким уровнем.
- **Выходы:** виртуальные кабели (VB-Cable A/B, Voicemeeter), наушники, колонки, выходы
  аудиоинтерфейса. Одна шина может идти на несколько выходов.
- **Синхронизация устройств:** у разных устройств разные часы. Нужна компенсация дрейфа
  (адаптивный ресемплинг по заполнению буфера), чтобы не было щелчков через час работы.
- **Режимы задержки:** обычный (shared 10 мс), низкий (exclusive WASAPI), в будущем ASIO.
- **Ducking:** голос приглушает музыку, звук саундборда приглушает голос — настраиваемые
  правила между полосами.
- Граф хранится в конфиге и меняется на лету без перезапуска движка (перестраивается атомарно).

### 2. Виртуальный кабель — автонастройка
- Определить, что установлено (VB-Cable, A+B, Voicemeeter). Если ничего — установить по одной
  кнопке с правами администратора и дождаться появления устройства.
- Сразу после установки: выставить формат 48 кГц, проверить, что кабель не стоит устройством
  по умолчанию для системных звуков (иначе звук Windows польётся в эфир), при необходимости
  вернуть прежнее устройство по умолчанию.
- Проверить работу: тон через кабель, замер уровня и задержки (уже есть, обобщить).
- Мастер для каждого приложения: показать, какое устройство выбрать в Discord / Dota / OBS,
  скриншот-подсказку и кнопку «Проверить» (ловим, что приложение открыло CABLE Output).
  Где можно — настраивать автоматически (конфиги Dota/CS2). Для Discord — подсказка и проверка.
- Сторож: устройство пропало или сменилось → переподключение и уведомление.

### 3. Визуализация голоса и звука
- На каждой полосе и шине: VU-метр с удержанием пика и отметкой перегруза, уровень в dBFS
  и громкость в LUFS.
- Окно голоса: осциллограмма (форма волны) в реальном времени, спектр (FFT, логарифмическая
  шкала), спектрограмма («водопад»). Переключатель «до эффекта / после эффекта».
- Порог гейта и шумодава прямо на графике — его можно тянуть мышью.
- Передача в интерфейс: бинарный WebSocket, 30–60 кадров/с, уже уменьшенные данные
  (min/max на пиксель, 64–128 полос спектра). Отрисовка в Canvas/WebGL. Нагрузка на CPU — до 2%.

### 4. Саундборд
- Сетка кнопок: страницы/банки, цвет, иконка или эмодзи, картинка, подпись, горячая клавиша,
  индикатор проигрывания с прогрессом.
- Режимы кнопки: один раз, перезапуск, стоп по повторному нажатию, пока держишь, зацикливание,
  случайный звук из группы, очередь.
- У каждого звука: громкость, шины (эфир / мониторинг / оба), кулдаун, fade in/out,
  свой пресет эффектов (live), ducking.
- Добавление звуков: перетаскивание файлов, запись с микрофона или системного звука
  («записать последние 30 с» — replay-буфер), импорт из ссылки, TTS.
- Встроенный редактор звука: обрезка по форме волны, fade, нормализация, срез тишины,
  смена скорости и высоты тона, «запечь» пресет в файл.
- **Комбо и цепочки:** макрос = последовательность шагов (звук, пауза, смена пресета,
  TTS, нажатие клавиши, звук поверх голоса). Наложение звуков слоями. Звук через пресет
  (например, сирена «по рации»). Голос + подложка (эффект «в эфире» с шумом рации).
- Поиск, теги, избранное, импорт и экспорт наборов (zip: звуки + раскладка).

### 5. Аппаратное управление
- MIDI-контроллеры (Launchpad, nanoKONTROL, любые): обучение «нажми кнопку на контроллере»,
  фейдеры → громкость полос, кнопки → звуки, подсветка кнопок (обратная связь о проигрывании).
- Stream Deck: плагин или подключение через локальный API (WebSocket).
- Локальный API (HTTP/WebSocket с токеном) для внешних устройств и скриптов.
- Бинды клавиатуры и мыши: аккорды, двойные нажатия, удержания (уже есть combo).

### 6. Мини-панель поверх всех окон (оверлей)
- Отдельное маленькое окно WebView2: горизонтальная полоса с кнопками звуков и пресетов
  и их биндами. Флаги окна: всегда сверху (TOPMOST), без значка на панели задач (TOOLWINDOW),
  полупрозрачное (LAYERED), без активации (NOACTIVATE) — клик не уводит фокус из игры.
- Настройки: какие кнопки показывать (страница, избранное, пресеты), размер, прозрачность,
  место на экране и монитор, свернуть до значка, автоскрытие, «клики насквозь»,
  показ/скрытие горячей клавишей.
- Индикаторы на панели: в эфире / mute / текущий пресет / уровень голоса.
- Ограничение: поверх игры в эксклюзивном полноэкранном режиме не видно. Пользователю это
  объясняем и предлагаем оконный режим без рамки.

### 7. Профили
- Профиль = граф + раскладка саундборда + пресет + бинды. Автоматическое переключение по
  активному приложению (Dota → профиль «Дота», Discord → «Общение»), ручное — горячей клавишей.

### 8. Интеграции — отдельные вкладки
- **Dota 2** (вынести всё текущее сюда): GSI, игровое время, таймеры рун и Рошана, события,
  кнопка голосового чата из биндов, параметр запуска, скрипт «ганк на миде».
- **Discord:** мастер настройки устройства ввода и вывода, подсказки по шумоподавлению
  (Krisp выключить, если работает наш шумодав), горячая клавиша PTT, проверка.
- В будущем: CS2 (GSI), OBS (WebSocket: сцены, отдельная шина для стрима), Twitch-чат → TTS.
- Интеграция — модуль с общим интерфейсом: Detect(), Setup(), Status(), События → скриптам.

### 9. Скрипты
Сохранить текущий API и расширить его: управление полосами и шинами (`mixer.gain("mic", -3)`),
саундборд (`board.play("pad:3")`), MIDI (`midi.on(...)`), события интеграций
(`on("dota:death")`, `on("app:discord:focus")`), запись звука.

### 10. Тесты и диагностика
Мастер «Проверить всё»: наушники → микрофон → кабель → каждое приложение. Плюс тест любого
маршрута, отчёт о задержках, нагрузке CPU и опустошениях буфера (xruns). Диагностический
пакет одним файлом (лог + конфиг + список устройств).

## Интерфейс (главные разделы)
Пульт (полосы, шины, матрица) · Саундборд · Голос (пресеты + визуализация) · Звуки (библиотека,
редактор) · Управление (клавиши, MIDI, Stream Deck) · Интеграции (Dota, Discord, …) · Скрипты ·
Тест · Настройка · Журнал. Тёмная тема, компактно, всё доступно с клавиатуры, крупные индикаторы.

## Данные
config.json v2 с полем `version` и автоматической миграцией с v1 (текущий формат).
Разделы: devices, graph {sources, buses, outputs, routes}, board {pages, pads}, sounds,
presets, profiles, bindings {keys, midi}, integrations {dota, discord, …}, overlay, ui.
Сохранение атомарное, резервная копия последних 5 версий.

## Нефункциональные требования
- Задержка голоса ≤ 20 мс (обычный режим), ≤ 10 мс (низкий). CPU в простое ≤ 2%, с визуализацией ≤ 4%.
- Работа сутками без щелчков и роста памяти. Переподключение устройств без перезапуска.
- Один exe + папка данных. Автообновление из GitHub Releases с подписью и откатом.
- Тесты: DSP и граф — юнит-тесты на синтетических сигналах; интеграции — на фейках;
  CI собирает Windows-сборку на каждый push.

## Как работать
Перед задачей — коротко план и что затронет. Маленькие проверяемые шаги. После шага —
`go vet`, тесты, сборка под Windows, обновить README/CHANGELOG. То, что нельзя проверить
без реальной Windows, явно помечать «проверить на системе».
Не ломать существующие функции и конфиги пользователей.
